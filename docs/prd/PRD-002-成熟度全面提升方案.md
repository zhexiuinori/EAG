## 1. 现状审计结论

### 1.1 权限与安全（最薄弱，硬伤明确）

已实现的部分比预想完整：用户 CRUD 有管理界面（Settings）、scrypt 加盐哈希、TOKEN_SECRET 持久化在 `<USERS_DIR>/token-secret`、角色 `admin|user` + `canManageConsole` 双维度、治理侧有 command-policy / fs-gate / egress / approval / audit 一整套。

但有四个硬伤：

| # | 问题 | 位置 | 风险 |
|---|------|------|------|
| S1 | **Token 永不过期**：`issueToken()` 产出两段式 token（userId + HMAC），`verifyToken()` 无 TTL，token 一旦泄露永久有效 | user-service.ts | 高 |
| S2 | **登录无限流**：`login()` 只审计失败、不做任何限流，可无限次爆破 | user-service.ts | 高 |
| S3 | **密码策略过弱**：`changePassword()` 仅校验 `length >= 6` | user-service.ts | 中 |
| S4 | **默认口令不强制改**：初始 admin 密码 `admin123`，登录后无任何强制修改引导 | user-service.ts / Login.tsx | 高 |

### 1.2 功能

- 强项：多 Agent（worker）管理、知识库、MCP 治理、审批中心、审计日志、Swarm 编排均已落地，不是空壳。
- 缺口：AgentHome 五个页签（进度/文件/变更/用量）目前为占位（`feat/app-activity-agent-home` 分支已建壳）；多 Agent 并行页签、可编辑文件树、委派链可视化未做；审批中心缺批量操作与筛选；审计日志缺导出与检索。
- 会话/动态：`/app/activity` 全部动态页已在 `feat/app-activity-agent-home` 分支实现，待合并。

### 1.3 界面

- 强项：React 19 + Tailwind 4 + zustand，已有 Sidebar/双端路由/设置中心骨架。
- 缺口：无登录失败原因的差异化提示（统一"用户名或密码错误"——安全上合理但锁定时应提示）；无密码强度反馈；无会话过期处理（401 后无引导回登录页的统一拦截）；缺空状态/加载态规范；无深色模式。

### 1.4 工程

- `chore/lint-vitest-governance-tests` 分支已补齐 ESLint 9 flat config + Vitest + 46 条真实断言测试（command-policy / fs-policy / approval-service），待合并。
- 缺口：CI（GitHub Actions）缺失——lint/test/typecheck 没有自动化门禁；用户域（user-service）无测试。

## 3. B1 权限加固包——需求明细（本批实现）

### 3.1 Token 过期（S1）

- token 升级为三段式：`base64url(userId).base64url(issuedAtMs).base64url(HMAC)`，HMAC 覆盖 `TOKEN_SECRET|userId|username|passwordHash|issuedAtMs`。
- 绝对有效期 **12 小时**；`verifyToken()` 校验签名 + 过期，过期/旧两段式一律拒绝（旧 token 登录态失效，用户需重新登录一次，可接受）。
- 改密码后 passwordHash 变化 → 旧 token 自动失效（沿用现有 HMAC 设计，天然满足）。

### 3.2 登录限流（S2）

- 按 username 维度计数：**连续失败 5 次锁定 15 分钟**；锁定期间直接拒绝并审计 `login.locked`；成功登录清零计数。
- 计数存内存即可（重启清零，风险可接受），不落盘。
- 登录返回改为可判别结果：成功 / 凭证错误 / 已锁定（含剩余秒数），由调用方映射 HTTP 401 / 423。

### 3.3 密码策略（S3）

- 新增 `passwordPolicyError(pw)`：**最少 8 位，必须同时含字母和数字**；返回错误文案或 null。
- `changePassword()` 与管理员重置密码均走此校验。

### 3.4 默认口令提醒（S4）

- 登录成功但密码等于初始值 `admin123` 时，返回 `passwordWeak: true`；前端登录后弹强制提示（toast + 跳转设置页改密入口），不阻断登录（避免锁死唯一 admin）。

### 3.5 前端配合

- `lib/ipc.ts` `authLogin` 透出新结果结构；`Login.tsx` 按结果展示：凭证错误（原文案）/ 已锁定（"账号已锁定，请 N 分钟后重试"）/ 弱密码提醒。
- server 端 `/auth/login`：锁定返回 **423 Locked** + `{ error, retryAfterSec }`。

### 3.6 验收标准

- 新 token 三段式，过期样本（issuedAt 伪造为 13 小时前）验证失败；旧两段式 token 验证失败。
- 同一账号连续 5 次错误密码后第 6 次即使密码正确也返回锁定；锁定状态 423；正确登录后计数清零。
- `changePassword` 拒绝：`abc`、`12345678`、`abcdefgh`（纯字母）；接受 `abcd1234`。
- `npx vitest run` 全绿（含新增 user-service.test.ts），`npm run lint` 0 error，`tsc --noEmit` 通过。

## 4. 风险与限制

- token 改三段式后，所有现存登录态失效一次（用户重新登录），属于安全修复的合理代价。
- 限流为内存态，多实例部署（当前为单机 Electron + 本地 Express）不适用，当前架构下够用。
- 锁定时长/阈值写死常量，B5 可考虑进设置页可配。
