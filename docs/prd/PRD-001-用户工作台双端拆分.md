## 一、目标与成功指标

**目标**：把 EAG 从"治理控制台形态"收口为"双端产品"——用户端（/app，"我用 AI 干活"）与管理端（/admin，"我管住所有 AI"）各司其职，消除设计与实现的漂移。

**成功指标**（验收时逐条核对）：

1. 非管理员用户登录后只接触用户端术语（助手 / 会话 / 动态 / 用量），任何页面不出现 Worker、Policy、Audit、Governance 等治理术语（管理端除外）。
2. 用户端首页即 Agent Portfolio：卡片呈现状态、模型、知识库、预算、共享范围，无需进入会话即可感知"我的 AI 团队"。
3. 用户能在一个页面看到所有助手的最新动态（全部动态），不必逐个进入会话。
4. 管理端全部页面在 `/admin/*` 下且受 `RequireAdmin` 守卫；非管理员直接访问 `/admin/*` 被拦截。

## 二、现状基线（评审时核实的代码事实）

评审于 2026-09-25 对照源码（`src/desktop/renderer/src/`）核实，方案中的 P0 项**大部分已落地**：

- ✅ 路由拆分已完成：`/app`（Workspace、WorkChat）与 `/admin/*`（10 个页面，均有 RequireAuth + RequireAdmin 守卫），见 `App.tsx`。
- ✅ 用户首页已是 Agent Portfolio：`Workspace.tsx` 卡片含运行状态、模型、知识库数、预算上限、团队共享标签。
- ✅ 侧边栏术语已分离：用户端为"我的助手 / 会话列表"，管理端为"治理控制台"导航，见 `Sidebar.tsx`。
- ✅ 开发调试痕迹已清理：全仓检索无 `build 0918-3`、`桌面端可用`、`Working...` 残留。

**因此本 PRD 的有效范围 = 原方案的 P0 残留项 + P1 + P2**，不重复建设已完成部分。

## 三、范围

### 3.1 本期做（In Scope）

| 编号 | 需求 | 原优先级 | 说明 |
|---|---|---|---|
| R1 | 全部动态页 `/app/activity`：跨 Agent 时间线 | P1 | 聚合当前用户各助手的会话活动；数据源先用本地会话索引（`lib/sessions.ts`），执行总线聚合留到后续迭代 |
| R2 | Agent 工作区壳 `/app/agent/:workerId`：对话 / 进度 / 文件 / 变更 / 用量 五个 tab | P1 | 本期落地 tab 骨架与导航；对话 tab 复用现有 WorkChat；进度 / 文件 / 变更 / 用量为占位实现，标注接入点 |
| R3 | 用户端侧边栏增加"全部动态"入口 | P1 | 位于"我的助手"分组上方 |
| R4 | 工程基线：ESLint + Vitest 接入，治理三链路（command-policy / policy / approval-service）首批单测 | — | 原方案未覆盖，评审新增；治理代码无测试是企业级产品的硬伤 |

### 3.2 本期不做（Out of Scope）

- 多 Agent 并行标签页 / 分栏（P1 后半，依赖会话状态重构，单独立项）
- 委派链可视化（P2）
- 用户可见的预算 / 用量 / 权限完整展示（P2，R2 的用量 tab 仅占位）
- 文件浏览器升级为可编辑文件树（P1，依赖 fs-gate 的读路径打通，单独立项）
- 用户自建 Agent（待确认项 T2 未决策前不做）

## 四、验收标准

### R1 全部动态

- 访问 `/app/activity` 展示当前用户所有助手的会话时间线，按更新时间倒序。
- 每条动态可点击跳转到对应会话 `/app/chat/:workerId/:sessionId`。
- 无任何会话时展示空态引导，不报错。

### R2 Agent 工作区壳

- 访问 `/app/agent/:workerId` 展示该助手的五个 tab：对话 / 进度 / 文件 / 变更 / 用量。
- 对话 tab 内嵌跳转现有 `/app/chat/:workerId`；其余 tab 为占位组件，明确标注后续接入点。
- 侧边栏助手列表项进入的默认页面保持 `/app/chat/:workerId` 不变（不破坏现有路径）。

### R3 侧边栏入口

- 用户端侧边栏"我的助手"分组上方出现"全部动态"，点击进 `/app/activity`，当前路由高亮正确。

### R4 工程基线

- `npm run lint` 真实执行 ESLint（不再是 echo 占位），对 `src/` 完成检查。
- `npm test` 真实执行 Vitest，覆盖 command-policy / policy / approval-service 三模块，断言均为真实行为断言（无"只判断不为 undefined"的假测试），全部通过。
- `npm run typecheck` 不引入新增错误。

## 五、关键假设

1. "全部动态"本期数据源为本地会话索引；审计 / 执行总线聚合是正确终态，但跨进程依赖重，放后续迭代（对应待确认项 T3）。
2. 单进程 Electron 形态本期不动；多用户集中化是架构级议题，另立架构决策记录（ADR）。
3. 沿用现有设计体系（Tailwind 主题 token、PageShell / StatCard / card 组件），不引入新视觉语言。

## 六、风险与限制

| 风险 | 等级 | 缓解 |
|---|---|---|
| R2 占位 tab 被误认为已完成 | 中 | 占位组件内明确标注"待接入"及接入点说明 |
| 本地会话索引仅存于浏览器 localStorage，换设备丢失 | 中 | 本期接受；跨端一致性见 T4 |
| 审批服务为模块级单例状态，测试需隔离 | 低 | 测试使用独立 ID 与临时目录（EAG_APPROVAL_DIR 覆盖） |

## 七、待确认项的决策建议（原方案"六、待确认"收口）

| 编号 | 问题 | 决策建议 |
|---|---|---|
| T1 | 用户端是否保留治理类 tab | **不保留**。用户端只呈现"受控"弱提示（盾牌标识），治理配置全部留在 /admin |
| T2 | 用户是否能自建 Agent | **暂不允许**。自建连带权限与预算边界，需单独 PRD；当前由管理员分配 |
| T3 | 全部动态数据源 | **本期本地会话索引，后续迭代切执行总线聚合** |
| T4 | Web 与桌面端多 Agent 并行一致性 | **跟随 T2 之后的多 Agent 并行专项一并定义**，本期不承诺 |
