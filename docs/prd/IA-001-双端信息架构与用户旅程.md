## 二、导航结构

### 用户端侧边栏

```
EAG · Agent Workspace
├─ 全部动态            → /app/activity          【新增】
├─ 我的助手 (N)
│   ├─ 助手 A ●       → /app/chat/A
│   ├─ 助手 B ○       → /app/chat/B
│   └─ …（NEW 徽标 / 运行状态点）
├─（展开某助手后）会话列表：新会话 / 搜索 / 分组（置顶·今天·近7天·更早）
└─ 管理控制台（仅管理员可见）→ /admin/workers
```

### 管理端侧边栏（不变）

```
EAG · Admin Console
└─ 治理控制台：Inbox / 治理总览 / Workers / 知识库 / 定时任务 / Models / Audit / Policy / Swarm / Settings
   返回工作区 → /app
```

## 三、Agent 工作区（/app/agent/:workerId）页面结构

```
┌────────────────────────────────────────────────┐
│ 助手名 · 状态 · 模型 · [受控🛡]                  │
├────────────────────────────────────────────────┤
│ 对话 │ 进度 │ 文件 │ 变更 │ 用量                 │
├────────────────────────────────────────────────┤
│ 对话：引导卡 → 进入 /app/chat/:workerId          │
│ 进度：占位（接入点：执行总线 / Swarm 时间线）      │
│ 文件：占位（接入点：fs-gate 读路径 + FileBrowser）│
│ 变更：占位（接入点：diff review 服务）            │
│ 用量：预算上限 / 知识库 / 共享范围（卡片已有数据） │
└────────────────────────────────────────────────┘
```

## 四、关键用户旅程

### J1：用户上班第一件事 —— 看团队在干嘛

1. 登录 → 落在 `/app`（Portfolio：N 个助手、M 个运行中）
2. 点「全部动态」→ `/app/activity` 看到所有助手按时间倒序的会话动态
3. 点某条动态 → 直达 `/app/chat/:workerId/:sessionId` 继续追问

**验收**：全程不接触任何治理术语；3 步内到达目标会话。

### J2：围绕一个助手深度工作

1. `/app` 点助手卡片 → `/app/chat/:workerId` 对话
2. 需要看上下文 → 顶栏/卡片进入 `/app/agent/:workerId`
3. 「用量」tab 确认预算与知识库范围 → 回到对话继续

**验收**：用户能回答"这个助手花了多少钱、能看哪些资料"，无需问管理员。

### J3：管理员治理（不变）

1. 用户端侧边栏点「管理控制台」→ `/admin/workers`
2. 治理操作（策略 / 审批 / 审计）全部在 /admin 内完成
3. 「返回工作区」→ `/app`

## 五、术语表（两端语言边界）

| 用户端说 | 管理端说 |
