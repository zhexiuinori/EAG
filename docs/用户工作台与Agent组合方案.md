---

## 一、背景与问题

EAG 是一个企业级 AI 编码 Agent 治理平台，后端已支持**一个用户拥有多个 Agent**，但当前前端仍是"治理控制台"形态，不像给企业用户用的 AI 工作台。

核心问题：

- 用户侧混入大量治理/技术术语（Worker、policy、audit、governance）和治理指标，普通用户看不懂也不需要懂。
- 多 Agent 的价值没有表达出来：用户面对的是单个聊天框，而不是"我的 AI 团队"。
- 界面偏开发者/管理员风格，字号小、信息密、存在开发调试痕迹（如 `build 0918-3`、`桌面端可用`、`Working...`）。

---

## 二、核心思路

**把产品拆成两个独立入口，并把用户端做成"我的 AI 团队"工作台。**

- 用户端（`/app`）：面向企业使用者，主题是"我用 AI 干活"。
- 管理端（`/admin`）：面向 IT / 安全 / 管理员，主题是"我管住所有 AI"。

### 两端的差异

| 维度 | 用户端 | 管理端 |
|---|---|---|
| 入口 | `/app` | `/admin` |
| 侧边栏 | 我的助手、全部动态、我的会话 | Workers、策略、审计、审批、知识库、定时任务、Models、Swarm、Settings |
| 顶栏 | 助手选择、模型、主题、账户 | 通知、审批、运行状态、主题、账户 |
| 术语 | 助手、使用的模型、权限受限、操作记录 | Worker、Policy、Audit、Governance、Budget |

## 三、竞品调研与企业级三栏工作台

### 3.1 竞品参考（联网调研）

| 产品 | 布局 | 对 EAG 的启发 |
|---|---|---|
| Cursor / Windsurf | 左文件树 + 中代码编辑器 + 右 Chat/Cascade | 主操作区应是“任务/代码”，AI 是右侧助手 |
| OpenHands / Devin | 左会话列表 + 中对话/进度时间线 + 右文件/终端/浏览器 | 任务驱动 + 多面板，聊天只是其一 |
| GitHub Copilot Workspace | 左仓库/任务 + 中“计划→实现→测试” + 右审批/评论 | 强化可审查、可审批 |
| Glean | 左 Ask/会话 + 中对话 + 右来源/引用/相关文档 | 强调来源、权限、可信 |
| Dify | 管理端配置 + 用户端简洁对话应用 | 配置与使用分离，用户侧保持简洁 |

### 3.2 目标布局（企业级三栏）

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏: EAG │ 全局搜索(助手/会话/文件) │ 通知 │ 主题 │ 账户        │
├─────────┬──────────────────────────────┬─────────────────────┤
│ 左侧导航 │           主工作区             │   右侧活动面板(可折叠) │
│ 我的助手 │   [Agent 身份条]             │  ● 正在进行(实时)      │
│ 全部动态 │   ┌────────────────────┐    │  ● 计划/时间线         │
│ 助手列表 │   │ 对话流 / 工具卡片    │    │  ● 变更(diff)          │
│ 会话列表 │   │  [输入区]            │    │  ● 文件                │
│ 设置    │   └────────────────────┘    │  ● 用量/权限/知识库      │
└─────────┴──────────────────────────────┴─────────────────────┘
```

- **左 =“我的 AI 团队”**：助手列表（状态/模型）+ 全部动态 + 会话，不是管理菜单。
- **中 = 任务/对话主工作区**：Agent 身份条 + 对话 + 工具时间线。
- **右 = 上下文/活动面板**：正在进行、计划时间线、变更 diff、文件、用量、权限/知识库；可折叠。
- **顶 = 当前对象 + 搜索 + 通知 + 账户**，不做管理后台。
- **透明但不打扰**：权限 / 知识库 / 预算 / 被拦截，用“受控”盾牌 + 弱提示呈现，不把治理配置摊给用户。

## 三、用户端：我的 AI 团队

### 1. 首页：我的助手（Agent Portfolio）

进入 `/app` 先看到一组 Agent 卡片，而不是单个聊天入口。

每张卡片展示：

- 职责与标签（编码 / 审查 / 测试 / 文档）
- 运行状态（空闲 / 运行中，含"正在做什么"摘要）
- 使用的模型
- 可访问范围（个人 / 项目 / 仅某目录）
- 挂载的知识库
- 累计预算与上限
- 是否为团队共享

### 2. Agent 详情：工作区

每个 Agent 有自己的专属工作区：

- 对话：主聊天区（流式、Markdown、工具卡片、附件、@引用、队列）
- 进度：AI 正在做什么（分析 → 编辑 → 测试 → 完成）
- 文件：文件树 + 编辑/预览
- 变更：diff 列表 + diff review
- 用量：本 Agent 累计花费 / 会话数 / 模型

### 3. 全部动态：跨 Agent 时间线

一个统一视图，让用户不用逐个点进去就能看到所有 Agent 的最新动态。

### 4. 并行使用

支持同时打开多个 Agent 的会话/工作区，用标签页或分栏切换；一个 Agent 运行时不影响用户去另一个 Agent 干活。

### 5. 委派链可视化

用户能看到"谁把活交给了谁"：

```
AI 助手 A ──委派──▶ AI 助手 B（架构审查）
                      └─ 返回：审查报告
```

## 四、企业场景的特殊点

- 共享 Agent：卡片标明"项目组共享"，避免用户误解为私有。
- 权限/范围：标明"仅前端目录 / 仅文档 / 全项目"，防止误用。
- 预算：明确展示花费，避免不知情烧钱。
- 知识库：用户能知道该 Agent 能看到哪些内部资料。
- 审计可见性：用户能看自己 Agent 的操作记录（哪些被拦截、改了什么），治理配置留给管理员。
- 任务结果：用户能收到自己 Agent 定时任务/后台任务的结果，而非只有管理员能看。

---

## 五、优先级

1. **P0**：路由与布局拆分（`/app` 用户端、`/admin` 管理端）；用户首页升级为 Agent Portfolio；去掉开发调试痕迹。
2. **P1**：单 Agent 工作区增加"正在做什么"与进度时间线；支持多 Agent 并行；"全部动态"跨 Agent 时间线；文件浏览器升级为可编辑文件树。
3. **P2**：委派链可视化；用户可见的预算/用量/知识库/权限展示；任务结果通知。

---

## 六、待确认

1. 用户端是否保留受治理终端/文件工作区等治理类 tab？建议弱化治理叙事，强调"给 AI 用的资源"。
2. 用户是否能自建 Agent？若允许，需连带权限与预算边界收紧。
3. "全部动态"数据源：优先复用审计 / 执行总线 / 通知 / 委派记录做聚合。
4. Web 与桌面端多 Agent 并行行为需保持一致。
